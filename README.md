# UNTRACE

A minimal, local-first privacy browser for Windows 11, built on Tauri 2 and Microsoft Edge WebView2.

**Status: 1.2.0 (sleeping tabs; stronger ad blocking with uBlock Origin's lists and scriptlets); Milestones 1 to 9 are complete ([ROADMAP.md](ROADMAP.md)).** Tabs, navigation, bookmarks, sleeping tabs, settings with verified state, diagnostics, HTTPS-only mode, certificate enforcement with connection details, permission, external-application and download prompts, ad and tracker blocking (EasyList, EasyPrivacy), warnings before malware and phishing sites, tracking prevention, removal of tracking parameters, temporary tabs, per-site cookie deletion, clearing on exit, a "Your data" page, encrypted DNS through UNTRACE's own network layer (Automatic, or Strict with Quad9, Cloudflare, Mullvad or your own server) protection of your local network from websites, WebRTC kept inside the network layer, and hiding of the space blocked ads leave are in place, covered by a 57-step end-to-end self-check that Diagnostics can also run. Settings › Appearance offers System, Light, Dark and Black themes, an accent colour, and websites that follow the theme. Diagnostics also saves a security report and shows the activity log ([ROADMAP.md](ROADMAP.md)). Not ready for daily use.

## Requirements

- Windows 11 x64 with the WebView2 Runtime (preinstalled on Windows 11)
- Rust stable, MSVC toolchain (Visual Studio Build Tools with the C++ workload)
- Node.js 24

## Build and run

```powershell
cd app/ui; npm ci; npm run build; cd ../..
cargo build --release -p untrace
.\target\release\untrace.exe
```

If the checkout path is long, set `CARGO_TARGET_DIR` to a short folder: MSVC's linker cannot handle paths over 260 characters.

## Check

```powershell
powershell -File scripts/check.ps1
```

This runs formatting, lints (warnings are errors), unit tests, the UI lockfile install, audit and build, a release build, and the end-to-end **self-check**. It also runs `cargo deny` and `cargo audit` when they are installed. CI runs the same script ([.github/workflows/ci.yml](.github/workflows/ci.yml)).

The self-check can also be run on its own:

```powershell
.\target\release\untrace.exe --self-check report.json
```

It starts the real app in a separate data folder, checks the security boundaries end to end without network access, writes a report and exits with code 0 when everything passes. **Diagnostics › Run self-check** does the same from the app: a second UNTRACE opens in its own window and test folder, and the result appears per protection in Diagnostics and Settings.

## Data

Everything UNTRACE stores lives in `%LOCALAPPDATA%\UNTRACE`: settings, the audit log and the WebView2 data folders. The installed program sits in the same folder, with the data in its subfolders. The Diagnostics page lists them. For development, `UNTRACE_DATA_DIR` points UNTRACE at another folder; Diagnostics shows when that override is active.

What UNTRACE stores and sends is in the [privacy notice](PRIVACY.md), which the app also shows (Settings › About).

## Installing

UNTRACE installs for the current user, without administrator rights, from the installer on its GitHub release page. Until the installer is Authenticode-signed (D-016), Windows SmartScreen warns that it does not recognise the app. Compare the installer with `SHA256SUMS.txt` on the release page. UNTRACE checks once a day for signed updates and asks before installing one. Building a release is described in [RELEASING.md](RELEASING.md).

## Layout

| Path | What |
|---|---|
| `crates/untrace-core` | Settings, protection registry, address parsing, audit log. Platform-independent, `#![forbid(unsafe_code)]`. |
| `crates/untrace-webview` | Content views: WebView2 environment, container window, tabs, events, hardening. |
| `app/src-tauri` | Tauri shell: window, IPC commands, capability file, self-check. |
| `app/ui` | React + TypeScript interface. |
| `crates/untrace-net`, `crates/untrace-filter` | The network layer (proxy, encrypted DNS) and the block lists, element hiding and request matching. |
| `scripts/` | The full check, the release build and the third-party notices generator. |
| `fuzz/` | Fuzzing targets (cargo-fuzz, nightly; not built with the app). |
| `spikes/` | Experiments behind each milestone's decisions (not built with the app). |
